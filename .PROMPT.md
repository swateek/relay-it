## What the app does

Relayit listens for incoming SMS messages in the background and forwards them to one
or more destinations based on user-defined forwarding rules called **jobs**.

A job says: "whenever I receive an SMS from X, forward it to Y, Z, and W."

Sources can be a sender ID (e.g. `GSTIN`, `HDFCBK`), a raw phone number with country
code, or a saved contact name. Destinations can be WhatsApp, Email, or SMS — multiple
per job, each independently toggled.

The app is fully offline. No backend. No cloud. No Firebase. Everything lives on the
device.

## SMS listener — critical requirements

This must be implemented as a **foreground service** using `flutter_foreground_task`
so Android does not kill it. A persistent notification must be shown while the service
is running: *"Relayit is watching for messages."*

Inside the foreground task, use `telephony` to receive SMS:

```dart
telephony.listenIncomingSms(
  onNewMessage: (SmsMessage message) async {
    final jobs = await StorageService.getActiveJobs();
    for (final job in jobs) {
      if (_matches(job, message.address ?? '')) {
        await ForwarderService.forward(job, message);
      }
    }
  },
  listenInBackground: true,
);
```

Matching is case-insensitive partial string match:
```dart
bool _matches(Job job, String sender) =>
    sender.toLowerCase().contains(job.sourceValue.toLowerCase());
```

Do not block the SMS callback. Use `Future.microtask` if processing is heavy.

## Forwarding channels

| Channel | How | Silent? |
|---|---|---|
| WhatsApp | `url_launcher` → `wa.me/<number>?text=<encoded>` | No — opens WA UI |
| Email | `flutter_email_sender` native intent | No — opens mail app |
| SMS | `telephony.sendSms()` | Yes |

WhatsApp and Email open the respective app's compose screen. This is a known v1
limitation. Show a one-time in-app dialog explaining this the first time either
channel is triggered.

## Android permissions

Declare in `AndroidManifest.xml`:
```xml
<uses-permission android:name="android.permission.RECEIVE_SMS"/>
<uses-permission android:name="android.permission.READ_SMS"/>
<uses-permission android:name="android.permission.SEND_SMS"/>
<uses-permission android:name="android.permission.READ_CONTACTS"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
```

At runtime, use `permission_handler`. Show a custom in-app rationale dialog before
triggering the system permission dialog. If permanently denied, show a prompt to open
app settings. Request on first launch in this order: `RECEIVE_SMS` → `READ_CONTACTS`
→ `POST_NOTIFICATIONS`.
